# 第一轮增长迭代

本轮支持“理解用途 → 输入自己的条件 → 分享方案 → 回来继续规划”。沿用静态 Pages、官方数据、同一套模拟器和 Worker，不更改掉率、优化策略或会话账本。

## 方案分享

- “复制方案链接”无需生成图片。剪贴板不可用时显示可手动复制的输入框。
- 卡片和链接来自同一份已完成模拟输入。等待新结果、输入无效或模拟失败时，不允许分享旧结果；异步生成图片期间输入变化会丢弃旧图片。
- 图片中的二维码在浏览器本地生成，无外部二维码服务。二维码依赖只在生成图片时加载。
- v1 链接使用 `#plan=<base64url>`，携带轮换、已选目标、这些目标的已有部件数量、预算、队伍人数、精炼策略、预算/概率模式、目标概率和抽样次数。不包含全局收藏中的其他装备或会话账本。
- 链接内容可被收到链接的人读取。它是可分享的方案，不是加密备份。URL fragment 不随浏览器的页面 HTTP 请求发送。
- 只接受已发布且仍在目录里的轮换。未知版本、超长内容、非法设置、未知目标/零件、超出制作需求的数量均拒绝。结果按当前目录与模型重新计算，不是永久冻结的历史数值。
- 接收者进入临时预览：更改不保存，不自动恢复/迁移或覆盖现有会话。“用我的已有部件计算”只在预览中替换收藏；“返回我的规划”回到正常保存的状态。
- 分享语言切换与跳到规划区保留方案。只有真实分享按钮会调用系统分享，生成/复制本身不对外发帖。

## 双语页面

根 `index.html` 是唯一模板，`data/locales/en.json` 和 `zh-cn.json` 是词典。`npm run build:locales` 生成可直接读取的完整 HTML；两个入口共享 DOM、样式和 app。生成页面中的 JSON 是不执行的词典数据，网络词典失败时仍能使用页面内的同一份译文。

既有 `js/route-entry.js` 保留为旧缓存入口的兼容文件；新页面不加载它。FAQ 只解释工具已经支持的行为，没有依靠过期轮换或固定概率吸引点击。

## 统计现状与边界

2026-09-09 只读核查发现：生产 HTML 已注入 Cloudflare Pages Analytics 的 `https://static.cloudflareinsights.com/beacon.min.js`，配置仅有站点 token；当前脚本默认上报 `https://cloudflareinsights.com/cdn-cgi/rum`。原 `script-src 'self'` 与 `connect-src 'self'` 不允许这两项。

本轮仅在 `_headers` 中放行上述精确脚本与上报路径。保留 `default-src 'self'`、禁止内联脚本、禁止第三方 frame 和其他原有安全头；不复制 token、不重复安装统计脚本、不手工伪造 beacon。

这恢复的是已有访问统计的运行条件。上线前不能声称已经收到数据。上线后的验收应检查实际脚本加载、合法 beacon 请求、无相关 CSP 拒绝，再确认后台出现正式域名的访问数据。

Cloudflare Web Analytics 当前不支持 UTM 参数和自定义事件，因此本轮不宣称能统计主动规划人数、分享转化率或跨轮换留存。页面打开会自动模拟，`simulation_completed` 也不能直接当作主动使用量。参见 [Cloudflare Web Analytics FAQ](https://developers.cloudflare.com/web-analytics/faq/)。

先用已有后台观察访问量、来源站点和中英文页面差异，并在 Search Console 查看收录、展示和点击。下一轮若接入事件统计，再实现“主动改条件 → 对应结果完成并被查看 → 分享 → 分享访问”的口径；不得上传收藏明细、完整分享 URL 或会话事件。

## 本轮验收

1. `npm run build:locales`，然后 `npm test` 和 `git diff --check`。
2. 中英文首屏、FAQ、窄屏布局，直接访问语言入口无需先拉取整页模板。
3. 同一份方案链接还原后的预算、队伍、精炼、目标与已有数量一致；重复部件支持部分拥有。
4. 复制链接、剪贴板失败后的手动复制、结果 PNG 和二维码；模拟进行中不能分享旧卡片。
5. 在存在已保存收藏或会话时打开方案，预览修改后返回原规划，原数据仍然存在。
6. 无效/未知轮换链接显示清楚的提示；正常轮换、Worker、CDF、会话的既有测试继续通过。
7. 部署后再验真实域名和统计后台。当前本地测试不能代替这一步，也不代表自然流量已经增长。
